# Release and debug builds are split by FUNCONF_USE_DEBUGPRINTF

Debug printf was unconditionally present in the image: DPRINTF (include/debug.h) expanded to printf, and ~100 raw printf calls remained in main.c and the sensor headers, so the printf stack (mini_vpprintf, _write, twoway_strstr, float helpers, ~2.5 KB) could not be removed and the CH32V003's 16 KB flash did not fit. Release builds (ch32v003, ch32v006) now pass -DFUNCONF_USE_DEBUGPRINTF=0, making DPRINTF a no-op and the printf machinery link out; ch32v006-debug is the debug build (flag unset), where DPRINTF emits through the SDI console (ADR-0003). The raw printf calls were converted to DPRINTF, and driver-internal debug output follows the LibDriver pattern of a linked debug_print pointer gated by a DRIVER_*_WITH_DEBUG_PRINT flag, which is undefined in all builds, so no raw printf remains in driver files. After the change ch32v003 links at 14,332 of 16,384 bytes and neither release build contains a printf symbol or any 64-bit division helper.
