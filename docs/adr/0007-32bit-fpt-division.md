# Quantization uses 32-bit-only division instead of 64-bit fpt_div

The firmware quantization path (QUANTIZE_Q in sensor.h) called fpt_div, which multiplies by 2^16 and performs a 64-bit (fptd) division, pulling the libgcc _divdi3/_moddi3/_udivdi3/_umoddi3 helpers (~4.5 KB) into every build. All live call sites divide by compile-time constants that are multiples of 2^16 (i2fpt(125), 22000<<14, HQ_MAX2), and for such a B the quotient (A * 2^16) / B reduces to A / (B >> 16), so fpt_div_const in sensor.h is bit-exact and 32-bit-only. QUANTIZE_Q now uses it. div_test.c checks old-versus-new bit-exactness across the full temperature, pressure, and humidity ranges plus out-of-range values (~2.05B checks, 0 failures); the existing quant.c harness still passes. The generic fpt_div in the vendored fptc-lib is left untouched, as its remaining users are host-side only.
