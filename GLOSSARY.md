# Glossary

- **Address family** - sensor types that share one I2C address (0x40: HDC1080, HTU31D, SI7021, HTU21D); the first successful probe claims the address and later same-address sensors are disabled.
- **Ping** - address-only I2C transaction checking that a slave ACKs at its address; cheaper than a probe, it does not verify identity.
- **Probe** - the per-driver initialization handshake (identity register read, config write) that decides whether a sensor is detected on a bank; a bare ping ACK is not enough for detection.
- **Boot-then-identify** - probe pattern for sensors whose identity registers are readable only in an active state (ENS210): soft reset, disable low power, wait for boot, read PART_ID, restore low power (ADR-0009).
- **Sensor sleep** - a sensor's own low-power idle state between reads (SHTC3 sleep command, ENS210 low power, MCP9808 shutdown, BMP280 forced mode, ADT7410 one-shot mode). Avoid: deep sleep (MCU-side only, standby), shutdown.
- **Bank** - one downstream channel of the I2C multiplexer, hosting up to two sensors; banks are probed in sequence each loop, independently of each other.
- **Used-banks field** - the three 16-bit `used_banks.raw` fields in packet.h that accumulate the bank id of every encoded reading, one 2-bit slot per ordinal, with `|=`. They are wiped at the packet boundary by `packet_clear_readings()` so a frame starts clean; keeping `|=` is load-bearing inside a frame because each ordinal is written one at a time (ADR-0013).
- **Slot** - one of the two sensor positions of a bank (bank.h `BANK_MAX_SENSORS = 2`); the fetch loop emits readings with the slot index as ordinal. Slots are position-pinned: a slot means the physical position on the mux channel, not a sensor type, so a physically swapped sensor keeps its column (ADR-0014).
- **Sentinel** - placeholder reading emitted for a dead slot inside a partially-alive bank, so a surviving slot keeps its true ordinal. Values are a wire contract: 0xFFFF for 16-bit temperature/pressure, 0x00 for 8-bit humidity (0xFF = 99.6 %RH is a valid reading; 0.0 %RH never occurs). The backend filters sentinels before decoding (ADR-0014).
- **Reading ordinal** - a reading's position inside its bank in one frame, 0-based, restarted whenever the bank id changes; the wire protocol gives a reading no identity beyond (bank, ordinal), so the same physical sensor can renumber if one in front of it drops (ADR-0013, weather demo_sensor_id_drift.py).
- **Mux disconnect** - TCA9548A CHANNEL_NONE state: all downstream channels open. Sensors stay powered regardless, so it is not sensor sleep.
- **Arena** - shared bump allocator over a 128-byte pool used by sensor factories; only BMP280 allocates from it, and one such sensor (88 bytes) fits while two do not. Its clear retires the whole arena, which orphans no live pointer as long as both facts keep holding (ADR-0006).
- **Bus recovery** - forcing a wedged I2C slave to release the bus by toggling SCL and generating a STOP, followed by re-initializing the I2C peripheral.
- **Wedge** - the I2C bus stuck busy (SDA held low, or the peripheral's busy flag latched): every transaction times out with I2C_ERR_BUSY until bus recovery runs.
- **Clock stretching** - the slave holding SCL low to pause the master's clock while it is busy (e.g. converting a measurement). The master must not poll a transaction while the line is stretched; it either waits for the release or uses a protocol that avoids stretching.
- **Conversion time** - the sensor's processing delay between a measurement trigger and data-ready. The datasheet's maximum value governs communication waits, not the typical one (see ADR-0001). Where the datasheet publishes no maximum, waits keep at least ~1.2x the typical value (docs/sensor-timing.md).
- **Clock config shadowing (resolved)** - hazard where the vendored I2C library's own funconfig.h (48 MHz core, HCLK systick) was quote-included into the lib source's unit and shadowed the project's include/funconfig.h (8 MHz, HCLK/8 systick). Because Delay_Ms expands to a SysTick tick count computed per-unit, the shadow made Delay_Ms(12) in i2c_read_reg_delay wait ~576ms instead of 12ms (~48x), inflating the four humidity-sensor conversion waits to ~7s and producing the ~10.5s pre-sleep acquisition window. Fixed via platformio.ini `-include include/funconfig.h` so the project config wins every unit; verified lib_TU sees FUNCONF_SYSTEM_CORE_CLOCK=8000000, DELAY_MS_TIME=1000, Delay_Ms(12)=12000 ticks, work window 9.95s->10.83s (0.88s) vs ~10.7s before.
- **Hold-master mode** - a measurement protocol in which the sensor pulls SCL low for the whole conversion and releases it to signal data-ready; the master must wait for the release before reading. The HTU21D driver keeps this flag only as a routing choice; the glue swaps in the no-hold commands, so the wire traffic is no-hold (ADR-0001). The SHT3x/SHTC3 drivers spell the same choice as the clock-stretching flag on the single-shot command; the glue passes the non-stretching variant.
- **No-hold mode** - a measurement protocol in which the sensor frees SCL during conversion; the master waits the maximum conversion time (or polls) before reading. Used by SI7021, since ADR-0001 HTU21D, and since ADR-0004 SHT3x/SHTC3 (clock stretching disabled).
- **Raw value** - the sensor's un-converted register output, written by the driver to a *_raw parameter (integer counts, e.g. the AHT30 20-bit raw or 16-bit temperature codes). The firmware reads raw values and converts them in the wrapper layer; the drivers' float conversions are compiled out (ADR-0005).
- **Physical value** - a sensor reading in engineering units (degC, Pa, %RH); LibDriver calls it the "real data". With float output compiled out (ADR-0005) the drivers leave the physical-value parameter unwritten, the wrappers pass NULL for it, and the firmware builds physical values from raw values with fpt or float helpers.
- **Print-only sensor** - a sensor whose readings are consumed only by SDI printf logging in its wrapper and are never encoded into the HC-12 packet; marked by the OBTAIN_GAS result, which no packet-encoding branch matches (ADR-0011).
- **fpt_div_const** - 32-bit-only exact fpt division: when the divisor B is a compile-time constant multiple of 2^16, (A * 2^16) / B reduces to A / (B >> 16). Quantization uses it instead of fpt_div so no libgcc 64-bit division helpers are pulled in; it is bit-exact for those divisors and verified by div_test.c (ADR-0007).
- **fpt LSB** - 2^-16 (1.5e-5) of the natural unit for a Q16.16 fpt value.
- **Wire step** - the smallest decodable change of a packet reading: 1.9e-3 degC for temperature, 0.39 %RH for humidity, 0.34 Pa for pressure. Quantization errors are quoted in wire steps, not fpt LSB (ADR-0010).
- **fpt compensation** - a driver stage that turns raw register counts into an fpt physical value in fixed point, so the wrapper stores the driver's result instead of converting a float one. BMP280 is the only such driver (under DRIVER_BMP280_WITH_INT): its pressure core splits the one non-power-of-two divisor (p1) into two 32-bit divisions so no __divdi3 is pulled in, and keeps its fraction down to 1/256 Pa (ADR-0015). Stage-1 error 0.05 wire step, 0.97 end to end (make bmp280_bench).
- **t_fine** - BMP280's calibrated intermediate, 5120 units per degC, which the pressure formula depends on. The driver caches it in the handle as Q8.8 (~0.8 u degC), because Q16.16 does not fit the int32_t field and the pressure path does not resolve temperature finer than that (ADR-0015).
- **fpt compensation** - a driver-side raw -> physical conversion that runs entirely in int64 and writes fpt, leaving the wrapper no stage-1 conversion to do. BMP280 is the only driver like this, under `DRIVER_BMP280_WITH_INT`; every other driver computes in float or hands over raw counts (ADR-0005, ADR-0015).
- **t_fine cache** - the BMP280 temperature term the pressure conversion needs, carried between the two calls in the handle as Q8.8 of the datasheet unit (5120/degC, ~0.8 u degC). Q16.16 does not fit the handle's int32 field and the pressure path is insensitive to the cached precision (ADR-0015).
- **Stage-1 conversion error** - the raw -> fpt converter's own error, at most ~1.4 fpt LSB for the live sensors; two orders of magnitude below one wire step, so the packet quantizer dominates the final accuracy (ADR-0010). BMP280's driver-side fpt compensation stays at 0.008 (temperature) and 0.046 (pressure) wire steps (ADR-0015).
- **Round-to-nearest pre-bias** - QUANTIZE_Q adds Q_RANGE/(2*FPT_ONE) (half a wire step, derived from the range constants) before its truncating division, making it round to nearest; this halves the end-to-end error from 1 to 0.5 wire step (ADR-0010).
- **End-to-end conversion error** - the error that matters: raw -> fpt converter -> QUANTIZE_* -> uint16/uint8 packing -> DEQUANTIZE_*, compared against the exact datasheet truth; swept over all 2^16 raw inputs per sensor path by conv_test.c (make conv_test), which exits nonzero on regression (ADR-0010).
- **Chunk** - 17 bytes, the most the HC-12 forwards in one burst; the module truncates anything above. Larger payloads are sent as a sequence of chunks.
- **Passthrough mode** - HC-12 state (SET high) in which serial data on TX is forwarded to the radio. Also called data mode.
- **Command mode** - HC-12 state (SET low) in which the module accepts AT commands.
- **Sleep** - HC-12 low-power state (~22 uA) entered by AT+SLEEP. No data transmission while asleep; the module wakes by entering command mode. A freshly powered module rejects AT+SLEEP sent too soon after power-on (verified failing at ~0.3s module age); the firmware's 20s pre-boot delay lands past the readiness threshold - cold boot sleep verified on the first attempt at 20.6s module age. Wake-before-send makes any early rejection harmless for data.
- **Wake** - entering command mode to exit sleep before a transmission. The module ignores AT commands sent before its command-mode settle completes: the manual's 40ms after SET falling was verified failing, 150ms verified working (module replies OK+SLEEP).
- **MCU sleep** - CH32V00x low-power state, core off via WFE, SRAM and peripheral register contents held; timed wake via the auto-wakeup (AWU) timer.
- **AWU** - auto-wakeup unit: LSI (~128kHz) timer with prescaler (PWR->AWUPSC) and window (PWR->AWUWR, window = value + 1) that raises EXTI line 9 to wake the core.
- **Standby** - CH32V00x lower-power state (PDDS) with the regulator in low-power mode.
- **Core clock** - HCLK, here HSI (24MHz) divided by 3 via RCC->CFGR0.HPRE, set from FUNCONF_SYSTEM_CORE_CLOCK. SystemInit resets HPRE to /1, so the divider is re-applied after boot and after sleep/standby wake.
- **Known state** - the HC-12 can be in any state at power-up or after a failed transmission; the wake-send-sleep cycle and the boot sleep exist to guarantee a predictable state before each send.
- **Transmission cycle** - the per-packet sequence wake -> send (chunked) -> sleep.
- **SDI printf** - printf() output the target emits through the SWIO debug pin (bit-banged via the DMDATA register, set up by ch32fun's SetupDebugPrintf); the debug probe decodes it and forwards it to the host. It is not UART output: nothing appears on the serial pins.
- **Serial Monitor** - PlatformIO/VS Code monitor UI over a serial port; in this firmware it is wired to the SDI printf stream (minichlink -T bridged to a pty) rather than to an MCU UART, which is unused for logging. The raw-terminal alternative is the sdi_printf_monitor platform target.
- **Release build** - firmware build with FUNCONF_USE_DEBUGPRINTF=0: DPRINTF expands to a no-op and no printf machinery is in the image. ch32v003 and ch32v006 are release environments (ADR-0008).
- **Debug build** - firmware build with FUNCONF_USE_DEBUGPRINTF enabled: DPRINTF expands to printf and is emitted through the SDI console (ADR-0003). ch32v006-debug is the debug environment (ADR-0008).
- **Experimental sensor** - a sensor gated behind a per-sensor compile-time define (e.g. -DEXPERIMENTAL_ENS160) in a single debug environment; release builds never compile its probe entry (ADR-0011).
- **wtocol** - the weather wire protocol codec, standardized as a canonical C library in lib/wtocol (ADR-0014). Three layers: HC-12 wire frame (header + payload + CRC-8 DVB-S2), packet (sync 'W' + version + device id + sensor count + module blocks), and per-module payloads. The byte layouts are frozen; weather_backend/protocol.py is the wire truth.
- **Wire frame** - layer 1 of wtocol, the HC-12 frame over UART: `[hdr][payload][crc8]`. v1 headers are 3 bytes (to/from routing), v2 are 2; the payload size is a 6-bit field (0..63).
- **Packet header** - layer 2 of wtocol: sync + version + device id + sensor count. v1 uses a 6-byte device id (9-byte header), v2 a 1-byte id (4-byte header).
- **Wind module** - the 0x12 wtocol module: 6 buckets x 18-bit (speed 10-bit, dir 8-bit), exactly 14 payload bytes, empty buckets zeroed. Two copies of the codec once used 18 bytes here, producing frames the backend rejected (ADR-0014).
- **THPCompoundV2** - the 0x13 wtocol module, variable length: per-type config, bank lists, and quantized temp/pressure/humidity; pressure dequantizes over 88000..110000, unlike the v1 compound (0x11) which uses 300..110000 (ADR-0014).
